## 1．项目概述

### 1.1 背景与问题

客户会话在双方都无新消息后会长期保持「处理中」，占用客服与 AI 客服的接待资源，也让收件箱积压无效会话。客服运营人员需要一个统一的自动关闭规则，让长时间无新消息的会话按约定时长自动结束，无需人工逐个处理。

### 1.2 目标用户

| 用户 | 场景 | 目标 |
|---|---|---|
| 客服运营人员 | 收件箱中无响应会话持续积压 | 配置统一的会话自动关闭时长 |
| 团队管理者 | 需要核对团队的会话处理规则 | 查看当前生效的超时规则 |

### 1.3 产品定位、目标与范围

- 产品定位：设置模块是产品的全局规则配置入口，按业务域分组收纳低频配置项。
- 本期目标：提供收件箱域的「聊天超时」规则配置，完成「查看 → 调整时长 → 保存生效」的最小闭环。
- 本期包含：设置导航（收件箱分组）、聊天超时规则页。
- 本期不包含：其他设置分组与配置项、按团队或渠道差异化设置、规则的修改记录与审计。

## 2．信息架构

```text
设置（一级侧边栏入口）
└─ 收件箱（分组，可折叠）
   └─ 聊天超时（规则页）
```

核心路径：侧边栏「设置」→ 默认进入「聊天超时」→ 调整时长 → 保存 → 规则生效。

## 3．功能需求详述

### 3.1 设置导航

#### 页面目标与入口

- 用户任务：在设置模块内定位目标配置项。
- 入口：一级侧边栏「设置」菜单，进入后默认选中「收件箱 → 聊天超时」。

#### 内容与字段

| 区块 | 字段／内容 | 展示规则 | 默认值 |
|---|---|---|---|
| 导航标题 | 「设置」 | 固定展示于导航顶部 | — |
| 分组 | 分组名「收件箱」＋折叠按钮 | 分组可折叠／展开；折叠后隐藏组内配置项 | 默认展开 |
| 配置项 | 「聊天超时」 | 当前选中项以选中态展示 | 默认选中 |

#### 用户操作

| 操作 | 前置条件 | 系统行为 | 结果 |
|---|---|---|---|
| 点击分组折叠按钮 | 无 | 切换分组展开／收起 | 组内配置项随之显示或隐藏 |
| 点击配置项 | 无 | 右侧内容区切换至对应配置页 | 当前仅「聊天超时」一项 |

### 3.2 聊天超时

#### 页面目标与入口

- 用户任务：配置会话无新消息时的自动关闭时长。
- 入口：设置导航「收件箱 → 聊天超时」。
- 完成后的去向：保存后停留当前页，顶部出现成功反馈。

#### 页面结构

| 区块 | 内容 | 说明 |
|---|---|---|
| 页面标题 | 聊天超时 | 标题下分隔线通栏 |
| 规则说明 | 「选择会话没有新消息时的处理方式。」 | 说明该页配置的用途 |
| 规则卡片 | 规则文案＋时长输入 | 本期唯一一条规则 |
| 操作区 | 「取消」「保存」 | 仅在有未保存修改时出现 |

#### 内容与字段

| 字段 | 类型 | 必填 | 默认值 | 规则 |
|---|---|---|---|---|
| 规则文案 | 文本 | — | 「如果没有新消息，超过以下时长后关闭会话」 | 纯文本展示，其中「关闭会话」加粗强调；该规则固定开启，不提供关闭入口 |
| 超时时长 | 数字输入 | 是 | 15 | 单位「分钟」；取值范围 1–1440；输入超出范围或为空时自动修正为边界值 |

#### 用户操作

| 操作 | 前置条件 | 系统行为 | 结果 |
|---|---|---|---|
| 修改超时时长 | 无 | 输入或步进调整分钟数 | 操作区出现「取消」「保存」 |
| 点击「保存」 | 存在未保存修改 | 校验并保存当前时长 | 提示「聊天超时设置已保存」，操作区消失；规则即时生效 |
| 点击「取消」 | 存在未保存修改 | 放弃本次修改 | 时长恢复为上次保存值，操作区消失 |

#### 状态与校验

| 场景 | 页面表现 | 处理规则 |
|---|---|---|
| 无未保存修改 | 不展示「取消」「保存」 | 页面为只读浏览状态 |
| 输入为空或小于 1 | 输入框自动修正为 1 | 以修正后的值参与保存 |
| 输入大于 1440 | 输入框自动修正为 1440 | 以修正后的值参与保存 |
| 保存失败 | 待确认 | 待确认 |

## 4．关键业务规则

### 4.1 会话自动关闭规则

```text
会话产生最后一条消息 → 计时开始 → 超过配置时长仍无新消息 → 系统自动关闭会话 → 会话进入「已结束」
```

- 计时起点：会话中任意一方最近一条消息的发送时间；出现新消息则重新计时。
- 聊天超时规则固定开启，超时时长全局唯一，对全部渠道、全部 AI 客服的会话生效，不支持按团队、渠道或客服差异化配置。
- 调整时长保存后对计时中的会话即时生效，按新时长重新判定。
- 会话自动关闭后的通知文案、是否允许客户重新发起会话：待确认。

### 4.2 保存流程

```text
修改时长 → 出现「取消／保存」 → 保存 → 校验（范围修正） → 写入全局配置 → 成功反馈 → 规则生效
```

权限规则：当前不区分角色，所有可访问产品的用户均可查看和修改；按角色限制修改权限为迭代假设。

## 5．数据模型与字段定义

### 5.1 全局配置（SettingsConfig）

| 字段 | 类型 | 必填 | 来源／用途 | 说明 |
|---|---|---|---|---|
| chatTimeout.enabled | boolean | 是 | 系统固定 | 聊天超时规则开关，固定为 true，不对外提供修改入口 |
| chatTimeout.minutes | number | 是 | 用户输入 | 无新消息自动关闭时长，单位分钟，默认 15，范围 1–1440 |

## 6．通用交互、异常与边界

- 重复提交：保存成功后操作区消失，无法对相同内容重复保存。
- 数据一致性：保存即时写入全局配置，刷新或重新进入后读取最近一次保存值。
- 不可逆操作：无；所有修改可通过再次编辑覆盖。

## 7．验收标准与迭代假设

| 验收项 | 通过标准 |
|---|---|
| 核心闭环 | 修改时长后点击「保存」，提示「聊天超时设置已保存」；重新进入页面，时长为保存后的值 |
| 表单校验 | 输入 0、空值或 1441 时分别被修正为 1、1、1440；修正后的值参与保存 |
| 操作区显隐 | 未修改时不展示「取消／保存」；修改后出现；「取消」恢复上次保存值并隐藏操作区 |
| 导航交互 | 点击「收件箱」分组折叠按钮，「聊天超时」项隐藏；再次点击恢复展示 |
| 数据一致性 | 保存后切换页面再返回，时长保持保存值 |
| 规则生效 | 保存新时长后，无新消息会话按新时长自动关闭（触发机制见 4.1 待确认项） |

### 待确认事项

- 会话自动关闭的执行机制：由服务端定时巡检还是消息事件驱动，判定频率与精度。
- 会话被自动关闭时，是否向客户与客服发送提示，以及提示文案。
- 保存失败路径的页面表现。

### 后续迭代假设

- 支持按团队、渠道或 AI 客服配置差异化超时时长。
- 增加规则修改记录与操作审计。
- 设置模块扩展更多分组（如通知、安全、账号），导航结构保持不变。
